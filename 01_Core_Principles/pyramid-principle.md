

# Pyramid Principle - Logical Writing & Thinking Skill

Based on Barbara Minto's *The Pyramid Principle: Logic in Writing, Thinking and Problem Solving*.

---

  

## Core Philosophy

  

**Lead with the answer.** Busy readers want the conclusion first, then the supporting arguments.

Never make the reader work to find the "so what."

  

The Pyramid Principle rests on one insight:

> Ideas in writing should always form a pyramid - one governing thought supported by a grouped,

> ordered set of arguments, each of which is itself supported by further arguments below.

  

---

  

## The Pyramid Structure

  

```

┌──────────────────┐

│ GOVERNING IDEA │ ← Single overarching message (the "so what")

└────────┬─────────┘

┌───────┴────────┐

┌────┴────┐ ┌────┴────┐ ┌────┴────┐

│ Key │ │ Key │ │ Key │ ← 3–5 supporting arguments

│ Point 1 │ │ Point 2 │ │ Point 3 │

└────┬────┘ └────┬────┘ └────┬────┘

... ... ... ← Supporting data / evidence

```

  

**Rules:**

1. Ideas at each level must be **summaries** of the ideas below them

2. Ideas at the same level must be **logically alike** (MECE)

3. Ideas within each group must be in **logical order**

  

---

  

## Two Ordering Approaches

  

### 1. Top-Down (Deductive) Order

Start with the main point, then explain why.

Best for: recommendations, executive memos, short emails to senior stakeholders.

  

```

Governing Idea → Argument 1 → Argument 2 → Argument 3

```

  

### 2. Bottom-Up (Inductive) Order

State observations → identify pattern → draw conclusion.

Best for: analysis documents, research reports, when the audience needs to be "taken on a journey."

  

```

Observation A + Observation B + Observation C → Therefore: Conclusion

```

  

**Default recommendation:** Use **top-down** unless the conclusion would be too surprising or the audience needs to build trust in the reasoning first.

## The SCR Situation-Complication-Resolution Framework

  

For narrative openings (especially executive summaries):

  

| Component | Question it answers | Example |

|---|---|---|

| **Situation** | What is the stable, agreed-upon context? | "Our customer retention rate is 78%, in line with industry average." |

| **Complication** | What has changed or threatens that situation? | "However, our top 20% customers (who drive 60% revenue) are churning at 2x the rate." |

| **Resolution** | What question does the reader now want answered? | "What should we do to retain high-value customers?" |

  

The SCR framework "hooks" the reader by creating a tension that the rest of the document resolves.

## MECE Thinking (Mutually Exclusive, Collectively Exhaustive)

  

A critical quality test for grouping ideas:

  

- **Mutually Exclusive**: No overlap between buckets. Each idea belongs to exactly one group.

- **Collectively Exhaustive**: No gaps. All relevant ideas are covered.

  

**Common MECE structures:**

- By process step (Step 1 → Step 2 → Step 3)

- By structural component (People / Process / Technology)

- By time period (Short-term / Medium-term / Long-term)

- By stakeholder (Customer / Company / Partner)

- By decision tree (If A then X; if B then Y; if C then Z)

  

**Test:** Can you add a fourth bucket that is meaningfully different? If yes - not exhaustive. Do any two buckets overlap? If yes - not exclusive.

## Logical Ordering Within Groups

  

Once ideas are grouped, choose the right sequence:

  

| Order type | When to use | Example |

|---|---|---|

| **Chronological** | Steps in a process, timeline of events | "First... then... finally..." |

| **Structural** | Physical components, org chart | North region / Central / South |

| **Ranking** | Importance, size, priority | "The #1 issue is X, followed by Y..." |

| **Causal** | Problem → cause → effect | "Because of X, Y happens, leading to Z" |

  

**Tip:** Avoid "random" lists. Every list must have an explicit ordering principle.

## The Governing Idea (The "So What")

  

The single most important sentence in any document. Must:

- Convey **one idea** only

- Be **assertive** (not a topic, not a question)

- Be **actionable or insightful** - something the reader couldn't conclude alone

  

| Weak (topic) | Strong (governing idea) |

|---|---|

| "This report covers our marketing performance" | "We should shift 40% of our marketing budget from display ads to content marketing" |

| "Analysis of customer feedback" | "Our NPS drop is driven by 3 fixable service failures, not product quality" |

## Step-by-Step: How to Apply This Skill

  

### Step 1 - Identify the task type

- **Writing from scratch**: Use SCR opening + pyramid body

- **Improving existing text**: Diagnose structural problems first (see Diagnostics below)

- **Structuring ideas**: Build the pyramid bottom-up first, then write top-down

  

### Step 2 - Clarify the governing idea

Ask: *"If the reader reads only one sentence from this document, what must they take away?"*

Draft a single assertive sentence. Test it: is it obvious? If yes, sharpen it.

  

### Step 3 - Build the supporting arguments

- Generate all supporting points (brainstorm freely)

- Group them using MECE logic

- Assign an ordering principle to each group

- Check: do the grouped points *prove* or *explain* the governing idea?

  

### Step 4 - Write the SCR opening (for documents/memos/presentations)

- **Situation**: 1–2 sentences of shared context

- **Complication**: The tension or problem

- **Resolution**: The question being answered (or the governing idea itself)

  

### Step 5 - Write the body top-down

- Start each section with its key point (not a topic sentence)

- Support with evidence/data/arguments below

- Use transitions that signal logical relationship ("Therefore...", "Because...", "However...")

  

### Step 6 - Quality check

See the checklist in `references/quality-checklist.md`

## Diagnostics: Common Problems & Fixes

  

| Symptom | Root cause | Fix |

|---|---|---|

| "I don't know what this document is saying" | Missing or weak governing idea | Rewrite the opening with a clear assertive message |

| "This is hard to follow" | Ideas in chronological or brain-dump order | Regroup by logic, not by the order you thought of them |

| "The sections feel disconnected" | No pyramid - each section is a silo | Ensure each section heading is a key point that supports the governing idea |

| "There's too much detail upfront" | Bottom-up writing without top-down rewriting | Flip: state conclusion first, then support |

| "The list feels arbitrary" | No ordering principle | Apply chronological / structural / ranking / causal order |

| "Some points overlap" | Not mutually exclusive | Merge overlapping points or redefine the grouping principle |

| "Something feels missing" | Not collectively exhaustive | Use an issue tree or MECE framework to find the gap |

## Output Formats

  

Depending on the user's request, produce:

  

- **Pyramid outline**: A structured outline showing governing idea → key points → supporting evidence

- **SCR opening**: A 3-paragraph executive summary opening

- **Full document**: Complete structured document (use `docx` skill for Word output)

- **Diagnosis + rewrite**: Annotated critique of the original + improved version

- **Issue tree**: Visual breakdown of a problem into MECE components

- **Slide structure**: Recommended slide titles that form a logical storyline

  

For Word document output, always invoke the `docx` skill.
